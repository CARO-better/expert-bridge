# 在任意领域找出术语

**这份文件不含任何领域词库，也不含固定的分类框架。** 词要当场搜，连"分成哪几维"也要从资料里得出来。

## 为什么不能预置

预置词库最大的坏处不是"覆盖不全"，而是**诱导模型跳过搜索**：
表里有词就抄表，表里没有就以为这个领域没术语，然后开始编或者放弃。两种结果都错。

同样的道理适用于**分类框架**：任何"六维度""四象限"都是某个领域的投影。
拿设计领域的维度去切法律或财务，切出来的空格不是"这一维没问题"，而是"这一维根本不存在"——
而模型往往会把它误读成前者。所以这里只放方法，不放分类。

## 第一步｜先判"分歧类型"（逻辑推理，不用搜）

模糊评价之所以模糊，是因为用户把**"哪里不对"**压成了一个形容词。
任何"不对劲"都落在四种形态之一：

| 类型 | 用户在说什么 | 该反问什么 |
|---|---|---|
| **程度** | 多了 / 少了 | 是过了一点，还是方向就不对？ |
| **层次** | 整体 / 局部 | 是整体不像，还是某处别扭？ |
| **归因** | 表象 / 真因 | 你看到的现象，可能不是原因。是这个环节吗？ |
| **标准** | 不合规范 / 不合口味 | 是违反了这个领域的通行做法，还是只是你不喜欢？ |

这四类跟领域无关，因为它们是**判断的结构**，不是内容的分类。举例：

- "动画有点生硬" → 程度（缓动太线性）或 层次（只是某几个元素的问题）
- "文章读起来费劲" → 层次（结构）或 程度（句子太长）
- "我这模型不准" → **归因**（数据问题、指标选错、还是过拟合？）
- "这方案不够专业" → **标准**（不合行业惯例，还是不合评审口味？）

**归因和标准这两类最值钱**：外行最常犯的错就是把表象当病因，或者把"不合我口味"当成"做错了"。
判到这两类时，先纠正判断，再谈术语。

## 第二步｜维度不预置，让资料决定

不要去套任何现成的维度表。做法是：**搜到一批词之后，看它们天然分成几组**——一组就是一维。

```
搜"<领域> 术语"→ 拿到 30 个词
  ├─ 12 个都在讲速度、时长、停顿   → 这一组就是"节奏"
  ├─ 8 个都在讲材料、工艺、表面     → 这一组就是"质感"
  └─ 6 个都在讲规范、档位、验收     → 这一组就是"标准"

→ 这个领域分三维：节奏 / 质感 / 标准
```

分组来自资料本身，不是来自你的先验。**分组之后才知道该往哪个方向劈词。**

判断方法很简单：把词按"它们在解决什么问题"聚堆，能自然聚成 2~4 堆就是对的；
聚成 10 堆说明搜得太杂，换一个更具体的检索式重来。

## 第三步｜找该领域的"词汇表"，而不是逐个猜词

通用三招（先试这三条）：

**1. 搜术语表 / 教程大纲（最高效）**

```
<领域> 术语        <领域> glossary / terminology
<领域> 入门 教程     <领域> 学习路线
<领域> 新手 常见错误
```

目录、章节标题、术语表就是必备词汇清单，一次能拿十几个到几十个，而且**按学习顺序排好**——
这直接告诉你哪些词最挡路。

**2. 搜外行的困惑（最贴近用户）**

直接用用户的原话搜，不要先翻译成书面语：

```
动画 生硬 怎么解决
页面 看起来很土 怎么改
```

回答里出现的技术词就是术语，而且你能看到**它在解决什么问题**——这就是"它管什么"的答案来源。

**3. 搜反面与对比**

```
<某种做法> 为什么不好
<A> 和 <B> 的区别
```

对比句是术语富矿：作者必须同时给两个概念命名，才能把它们区分开。

再按领域形态补一刀（不同领域，"权威资料"长在不同地方）：

| 领域形态 | 该搜什么 | 为什么 |
|---|---|---|
| 学术 / 研究 | 综述（review）、教科书目录、领域年鉴 | 综述的第一节通常就是术语定义 |
| 手艺 / 制造 / 烹饪 | 配方、流派、老师傅的口诀、行话 | 术语以口传形式存在，藏在教学视频和论坛里 |
| 专业服务（法务、财务、医疗、咨询） | 实务指南、作业手册、检查清单、行业准则 | 准则文件本身就是术语标准 |
| 创意 / 内容（写作、影像、音乐） | 拉片分析、作品赏析、评审意见、投稿指南 | 评论者命名概念最勤 |
| 工程 / 软件 | 官方文档目录、规范（RFC / 标准）、API 索引 | 目录名即术语，定义准确 |

## 第四步｜挑词，劈给用户选

从候选里挑 **2~4 个**，硬性要求：落在**不同方向**，否则用户没得选。

**二选一**（只有一个分叉时最快）

> 你说的"卡"，是画面本身一顿一顿（帧率），还是该停的地方没停（节奏）？

**三选一 + 代价**（默认用法）

> 可能是三件事：A 速度曲线、B 帧率、C 缺细节。选错方向会白做一版，你更在意哪个？

**反例法**（用户说不清"要什么"时最有效）

> 你说的"高级感"，是不是指"不要那种一眼看出是模板的渐变＋大圆角＋彩色图标"？

反例法好用是因为：**人对"不要什么"的判断力，远强于对"要什么"的表达力。**

## 第五步｜反查定义，再写术语卡

拿到词**不要直接解释**。模型对术语的直觉解释经常差半步，而差半步比不解释更糟——
用户会拿着一个错的理解去提需求。

先搜一轮，读到至少两处**一致**的说法再写：

```
<术语> 是什么 / 定义 / 原理
<术语> 和 <相邻概念> 的区别
```

术语卡四行，最后一行是验收标准：

```
他说的：<用户原话>
业内叫：<术语>（<从业者实际使用的原文名>）
它管的是：<决定哪个结果>，同时说清<不管什么>
换成这个说法，你可以要求：<一条可验证的具体要求>
```

**落不到具体要求的术语，是装饰品，删掉。**

## 交叉验证与防编造

- 同一概念在**两个以上独立来源**出现，才算该领域的通用术语。
- 只在一个博客出现过一次的，写成"有人这么叫"，不要当行业标准。
- **原文名不必然是英文。** 多数技术领域英文是检索钥匙，但中餐、中医、中国法、戏曲这类领域
  用中文才搜得到东西。判断依据很简单：**用哪个词能搜到资料，哪个就是检索钥匙。** 拿不准就别硬配。
- **宁可少给一个词，也不要给一个搜不到的词。** 用户拿去搜、搜不到，迷茫会加倍。

## 搜不到时怎么办（降级，不要硬编）

1. 换两个同义词、换语言，再搜一轮。
2. 仍然没有 → 明说："这个方向我没搜到公认的术语。"
3. 然后**用描述性规格替代术语**：把模糊词换成可验证的数值或反例。
   外行不需要术语也能明确提要求，术语只是效率工具，不是必需品。
   这几种说法在任何领域都成立：**"要 / 不要"加一个具体例子、"多快 / 多慢"加一个数字、
   "像 / 不像"加一个对象。**
4. 绝对不要为了显得专业而造词。

## 检索预算

**3~5 轮**（默认值），不是越多越好。术语发现要的是"准"不是"多"：
搜太多会把上下文塞满、把回复拖慢，最后还是要回到"挑 4 个词"这一步。
一轮里能同时覆盖多个方向的检索式（"术语""区别""为什么不好"）优先。

## 没有联网能力时

直接说明："我现在不能联网，只能给你方向性的拆解，具体术语建议查 XX 类资料或问从业者。"
**不要假装搜过**，也不要凭记忆把术语当事实给出去。
