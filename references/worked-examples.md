# 一个完整走查（示范流程与篇幅，不示范领域）

> **读这份文件时的三条提醒：**
>
> 1. 例子讲的是"动效"，只是为了把步骤走完。换成"写曲子""做财报""准备答辩"，
>    流程一模一样，**里面的词、维度、现成资源的形态全部要换，而且要重新搜**。
> 2. 重点看第 2 步的**检索记录**：术语是当场搜的，连"该往哪几个方向劈"也是搜完才知道的。
>    如果你照着抄这些词，等于把整个技能跳过了。
> 3. 别把这里的"三维度"当成通用框架——它只对这一个领域成立。

目标篇幅：四块内容合起来 40~60 行，不超过一屏半。

---

**用户原话**：「我这个页面的动画有点生硬，想做得丝滑一点。」

## 第 0 步｜跳过

用户已经说清了"什么东西、什么毛病、想要什么"。**不问他"做过动效吗"**，直接往下走。

## 第 1 步｜概念（只给 2 个，因为真正挡路的就两个）

**缓动（easing）**
管什么：速度随时间怎么变——匀速、起步快、还是结尾慢慢停。
不管什么：不管动画多长，也不管精不精细。
你现在可以不管：贝塞尔曲线的数学、物理弹簧的参数。

**时长（duration）**
管什么：从开始到结束多久。界面动效的常识区间是 150~300ms。
不管什么：不管好不好看。时长对了也可能难看。

## 第 2 步｜检索记录（这步是重点）

| 搜了什么 | 拿到什么 | 用来干什么 |
|---|---|---|
| `UI 动效 术语` / `motion design glossary` | 一批词：easing、duration、stagger、spring、secondary motion、trigger | 候选池 |
| — | 按"解决什么问题"聚堆 → **速度类**（easing/spring）、**时序类**（duration/stagger）、**触发类**（trigger/hover） | **这三堆就是该领域的三维**，不是我预置的 |
| `动画 生硬 怎么解决` | "线性插值看着像机器走过场" | 确认用户的"生硬"最可能落在速度类 |
| `easing 和 spring 的区别` | 一个改速度曲线，一个模拟物理回弹 | 防止两个词混用说错 |
| `easing 中文` | 缓动 / 缓动曲线 | 中英对照 |

**注意顺序**：先拿整张词汇表 → 聚堆得出维度 → 才知道该往哪劈。
反过来（先想好"动画分几维"再去找词）就会套模板。

判分歧类型：用户说的是"生硬"，属于**程度**（少了缓动），不是层次问题（不是某几个元素坏了）。
所以劈词时不必问"哪一块"，直接问"要哪种变化"。

## 第 3 步｜劈词

你说的"生硬"，可能是三件事：

- **A. 速度曲线**：匀速运动看着像机器 —— 业内叫 easing / 缓动曲线
- **B. 起止太满**：从 0 直接到 100 再停住 —— 业内叫缺 ease-in / ease-out
- **C. 没有回弹**：所有元素同时到位，缺错落 —— 业内叫 overshoot 与 stagger

选错方向会白做一版。多数情况是 A，但你想要"有弹性"就是 C。

（用户选 A，并说"希望有一点点弹"）

## 第 4 步｜术语卡

```
他说的：丝滑一点、有一点点弹
业内叫：easing（缓动）+ 轻量 overshoot（回弹）
它管的是：速度随时间怎么变，以及到位后是否略微越过再回来。
          不管动画多长，也不管画面精不精细。
换成这个说法，你可以要求：入场用 ease-out 220ms，回弹幅度不超过 5%，只弹 1 次
```

## 第 5 步｜简报（必填三项 + 可选两项）

```
【目标】给现有页面的入场与悬停交互加动效，观感从"生硬"改为"顺滑，带一点弹性"
【成败判据】连看 10 遍，既不觉得"在等它"，也不觉得"没看清"
【明确不要】不要弹跳超过 2 次、不要旋转、不要同时动超过 3 个属性
【具体规格】easing = ease-out；duration = 220ms；overshoot ≈ 5%；列表间隔 40ms
【使用者 / 场景】产品官网首页，桌面端，用户停留 30 秒内
```

（没写"参考物"——用户没给，也不该由我编一个具体网站出来。）

## 第 6 步｜现成的

按"权威做法 → 可复用成品 → 同行经验"排，只报 3 个，每个说清三件事：

- **缓动曲线参考站**：查曲线长什么样，直接复制参数。免费，改造成本为零。
- **平台人机界面指南的动效章节**：给了时长与缓动的推荐档位，属权威做法，拿来当基准。
- **开源动画库**：授权各家不同（有 MIT 的，也有商用要付费的），接入成本从"包一层组件"到"重写交互"不等。

结论：这类需求用现成库的几个 API 就能改完，**不需要从零写动画系统**。
