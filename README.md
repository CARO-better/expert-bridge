# expert-bridge

一个给 **Agent 用的技能（Skill）**：帮完全没有相关经验的人，在陌生的领域里把事说清楚、做成。

不是领域知识包，而是一套**流程**——它不含任何领域的词表和分类框架，术语一律当场检索。

## 它解决什么问题

外行借助 Agent 干活，失败的链条几乎是固定的：

> 说不清术语 → 检索时用不上关键词 → 搜不到现成方案 → 只能让 Agent 从零造
> → 又贵又慢、质量不稳 → 用户以为是"自己不会用 AI"

技能按顺序补三处：**术语 → 简报 → 现成方案**。

## 它具体做什么

1. **判分歧类型**——把"不对劲"归到四类之一：程度 / 层次 / 归因 / 标准。
   外行最常犯的错是把表象当病因，或者把"不合我口味"当成"做错了"。
2. **检索术语**——搜该领域的术语表、教程大纲、权威目录，**搜完再按词的自然聚类决定这个领域分几维**。
   没有预置维度，也没有预置词表。
3. **劈开模糊词**——给出 2~4 个不同方向的候选术语让用户选，并说明选错的代价。
4. **产出简报**——3 项必填（目标 / 成败判据 / 明确不要）+ 4 项可选，可直接复制给任何 Agent。
5. **找现成的**——权威做法 → 可复用成品 → 同行经验 → 从零做。各领域的形态不同（代码是库、做菜是配方、写作是范文），不套用软件领域的假设。

## 安装

技能的标准单位是**目录**，不是单个文件。克隆或解压后，确认 `<skills 目录>/expert-bridge/SKILL.md` 存在。

```bash
# Claude Code（个人级）
git clone <repo-url> ~/.claude/skills/expert-bridge

# WorkBuddy
git clone <repo-url> ~/.workbuddy/skills/expert-bridge

# 项目级（团队共享）
git clone <repo-url> .claude/skills/expert-bridge
```

用 zip 的话，解压到 skills 目录即可。**注意别多套一层文件夹**（`expert-bridge/expert-bridge/SKILL.md` 会导致扫不到）。

## 依赖的 Agent 能力

| 能力 | 是否必需 | 没有时 |
|---|---|---|
| 联网检索 | **必需** | 第 2 步失效，只能做方向性拆解（技能内置降级话术，不会硬编术语） |
| 文件读写 | 可选 | 只影响"简报落盘、跨天续做" |
| 多轮对话 | 必需 | 劈词需要用户回一次选择 |

技能里只写能力名称（"联网检索""存成文件"），不绑定具体工具名，所以换 Agent 不需要改内容。

## 结构

```
expert-bridge/
├── SKILL.md                        流程、底线、反模式、自测方法
├── references/
│   ├── term-discovery.md           术语怎么找、怎么验证、搜不到怎么办
│   └── worked-examples.md          一个带检索记录的完整走查（仅示范流程与篇幅）
├── README.md
└── LICENSE
```

`references/` 只在需要时加载，不占常驻上下文。

## 已知限制

- **依赖搜索**。没有联网能力的 Agent 用它，第 2 步直接断，只能得到降级输出。
- **`worked-examples.md` 用的是 UI 动效做例子**。它示范的是检索记录和篇幅，不是领域内容；换成任何领域都要重搜。
- **中文优先**。description 里附了英文，但正文是中文；非中文对话下的效果没实测过。
- 四类分歧（程度/层次/归因/标准）是逻辑层面的归纳，不保证覆盖所有情况。

## 改它

改之前先看 `SKILL.md` 末尾的「维护时怎么验」：**只改 description 就只测触发，只改流程就只测输出**，一次只改一处。
两样一起改，出问题永远找不到原因。
